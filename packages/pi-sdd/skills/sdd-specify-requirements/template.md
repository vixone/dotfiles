# Product requirements: {{title}}

## Product overview

Describe vision, a specific measurable problem supported by evidence, and the user value. Distinguish observations from assumptions.

## Personas

Define distinct primary and secondary users with goals, pain points, roles, and relevant expertise. Do not invent demographic facts.

## Journeys

Map each persona's primary path, discovery and adoption context, errors, and recovery. Adapt to CLI or batch use rather than inventing UI.

## Feature requirements

Group public requirements into Must, Should, Could, and Won't for this scope. Assign stable requirement IDs. For each feature, provide a user story and Given/When/Then criteria for happy, error, and boundary cases.

## Detailed behavior

Describe user flows, business rules, and edge conditions for complex features. Keep implementation and API design out of this document.

## Success metrics

Give numeric adoption, engagement, quality, and business targets where relevant. Record units and measurement events, properties, and purpose.

## Constraints and assumptions

List platform, legal, budget, and scope constraints. Label assumptions that need evidence.

## Risks and mitigations

Record risk, impact, likelihood, and proposed mitigation.

## Open questions

List unresolved input and decision owners. An unresolved question blocks final approval unless the user explicitly approves an omission.

## Supporting research

Cite competitive, user, and market evidence where relevant. Do not fabricate research.

## Requirement coverage

Map each public requirement ID to task keys after decomposition. Put this mapping in the generated briefs as well. This is static coverage, never task progress.
