Write a self-contained handover. A fresh conversation continues from this alone.

Use these sections once each and omit empty sections:

## Goal
The intended outcome in one or two lines.

## Target
Repository, branch, worktree and files in scope. Include the explicit mx mission and task ids and open queue row ids.

## State
Done and verified, in flight, open worktrees, commits, pushed branches, compare or PR URLs and merge status.

## Findings
Facts with evidence: file, command, test output path or exact error.

## Decisions
Choices and reasons that the successor should retain.

## Dead ends
Failed approaches and why they failed.

## Next
Numbered steps. Step 1 must be concrete enough to execute. Name any operator decision or missing access that blocks it.

Keep conclusions, not a chronology or output dump. Prefix unverified claims with `UNVERIFIED:`. Preserve exact ids, paths and error strings. Close code fences. Aim for fewer than 60 lines.
